# MULTI_PERSONA_4_0 — 상담 스타일 시스템

> 브랜치 `feature/multi-persona-4.0` · 기준일 2026-11-09

## 1. 구조
3.0의 캐릭터(하루·도담·저울의 이름과 외형)는 그대로 두고, **상담 스타일을 독립된 축**으로 추가했다. 어떤 캐릭터든 다섯 스타일 중 하나로 상담할 수 있다.

| 스타일 ID | 표시 이름 | 상담 목표 |
|---|---|---|
| `strategy` | 전략형 | 장기 목표를 단계와 일정으로 나눈다 |
| `challenge` | 도전형 | 실패를 다시 시도할 수 있는 실험으로 바꾸고 대안을 찾는다 |
| `empathy` | 공감형 | 부담을 먼저 알아주고 작은 행동으로 연결한다 |
| `analysis` | 분석형 | 근거의 수준과 한계를 평가하고 논리적으로 비교한다 |
| `reflection` | 성찰형 | 질문으로 자신의 가치와 기준을 찾게 돕는다 |

각 스타일의 고유 ID, 표시 이름, 상담 목표, 말투, 질문 방식, 의사결정 접근, 필수 구성, 피할 패턴은 `web/src/lib/counsel/styles.ts`에 있다.

기획에서 참고한 다섯 인물 유형의 이름·이미지·대사·설정은 공개 UI와 프롬프트에 쓰지 않는다(단위 테스트로 금칙어 검사). 실존 인물과 작품 속 인물의 인용도 프롬프트로 금지한다.

## 2. 호환성
| 항목 | 처리 |
|---|---|
| 저장된 3.0 캐릭터 설정(`hufs-atlas:lounge:seniors:v1`) | 변경 없음 |
| 스타일을 저장한 적 없는 사용자 | 캐릭터 성격에서 기본값 결정: 따뜻한 → 공감형, 현실적인 → 전략형, 분석적인 → 분석형 |
| `style` 없는 3.0 형식 API 요청 | 같은 기본값으로 처리 |
| 스타일 저장 위치 | `localStorage`의 `hufs-atlas:counsel:style:v1` (브라우저 단위, 서버 저장 없음, 전체 초기화 시 삭제) |

요청의 스타일 값은 서버에서 다시 검증한다(`sanitizeStyleSetting`).

## 3. 사실과 관점의 분리
```
질문·프로필 → 검색·비교 계산 → 근거 블록(ctx)
                                 ├─ 사실 답변 (스타일 무관, 캐시 공유)
                                 └─ 스타일 답변 (같은 ctx, 설명 관점만 변경)
```
- 사실 답변의 캐시 키에는 스타일이 없다. 스타일을 바꿔도 같은 사실 답변을 재사용한다.
- 캐시 키에는 근거 저장소의 수정 시각이 들어간다. 승인과 동의 철회는 즉시 반영된다.
- 스타일 답변은 생성 후 `counsel/guard.ts`로 검사한다. 근거에 없는 수치, 확률, 학점 평가, 사례 기간의 예측화, 채용 조건 단정, 가짜 경험이 있으면 재생성하지 않고 같은 사실로 만든 템플릿으로 대체하며 화면에 알린다.
- 위기 신호와 공식 정보 질문에는 스타일을 적용하지 않는다.

## 4. UI
- 상담창 안의 한 줄 선택기. 펼쳐도 상담 패널 안에서만 열려 캠퍼스 화면을 가리지 않는다.
- 스타일을 바꾸면 "같은 질문을 다시 듣기"를 제공한다. 사실 답변 캐시가 적중해 LLM은 1회만 호출된다.
- 선택 전 패널에 선배 카드를, 대화 중에는 선배 얼굴을 표시한다.
- 대기 중에는 경과 시간과 "그만 기다리기"를 표시한다.

## 5. 측정 요약
상세는 `VALIDATION_4_0.md`. 실제 Qwen3-14B 72턴에서 표지 표현이 각 스타일에 맞게 나뉘었다(도전형의 도전 표지 4.5, 분석형의 분석 표지 4.0, 성찰형의 성찰 표지 7.5). 같은 질문에서 스타일 간 답변 유사도(Jaccard)는 0.12~0.20이었다. 표지 표현은 대리 지표이며, 상담 품질은 사용자 연구로 확인해야 한다.
