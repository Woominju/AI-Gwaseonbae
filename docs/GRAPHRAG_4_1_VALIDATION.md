## 4. 기존 RAG(A)와 GraphRAG(B) 비교
`web/scripts/eval-graphrag.ts` · 13문항 · 원문 `results/llm41/graphrag_eval.json` (개선 전 `graphrag_eval_v1.json`)

| 항목 (관계 탐색 5문항) | A | B |
|---|---|---|
| 필요한 관계 검색 | 해당 없음 | 5/5 |
| G-xx 인용이 있는 답변 | 0 | 4/5 |
| 답변 내 자료에 없는 과목명 (자동 후보 검사) | 0 | 0 |
| 첫 답변 중앙값 | 14.6초 | 18.1초 |

전체 13문항에서 없는 ID 인용 제거 1건, 가드로 대체된 답변 0건. 사실 조회는 규칙 답변으로 약 10~30ms (B), A는 LLM 호출 또는 일반 안내.

- **그래프가 유리한 질문:** 과목–역량–직무 연결, 개설·선수 과목. A는 "관련 수업을 검토하라"는 수준이었고 B는 구체적인 과목을 근거와 함께 제시했다.
- **기존 RAG로 충분한 질문:** 선배 경험담. "인턴십 준비" 질문은 관계 근거 0건이고 답변이 거의 같았다.
- **비용:** 관계 문맥이 길어져 응답이 약 3.5초 늘었다. 표본이 5문항으로 작다.

개선 과정: 1차 측정에서 인턴 진술이 과목 근거를 밀어내고, 역량을 과목처럼 쓰고, 과목 인용이 빠지는 문제를 원문에서 확인해 고쳤다.

## 5. 원문 검토에서 남은 문제
- "필수적입니다", "직접적으로 관련된", "충분히 가능합니다" 같은 과한 표현이 일부 남는다. 현재 가드는 이런 정도 표현을 잡지 못한다.
- "수학과에서 배우지 않는 경우가 많으므로"처럼 근거 없는 일반화가 있었다.
- 추론 연결(G-01)을 선배 수강 사례의 근거처럼 인용한 경우가 있었다.
- 자동 지표는 대리 지표다. 사람 평가 수준은 개발 중 표본 검토뿐이다.
