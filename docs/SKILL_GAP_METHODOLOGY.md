# SKILL_GAP_METHODOLOGY — 역량 추출·비교 알고리즘

구현: `web/src/lib/career/skillGap.ts`(순수 함수), `providers.server.ts`(추출). 모든 계산은 결정적이며 재현 가능합니다.

## 1. 역량 공간
역량은 기존 taxonomy의 정규화 ID(`python`, `sql`, `statistics` …, 30종)를 씁니다. 신규 기능 때문에 taxonomy를 바꾸지 않았습니다(기존 매칭 점수 회귀 방지).

## 2. 입력
- **S** — 학생이 프로필에 입력한 역량. 자유 텍스트를 `canonicalSkill`로 정규화합니다. 예: "파이썬"→`python`, "Java"→`programming`
- **NCS** — 직무 세분류의 능력단위 집합 U. 각 능력단위 u에는 매핑 역량 m(u) ⊆ 역량 공간이 있습니다. **m(u)는 서비스 설계 가정**이며 NCS 공식 매핑이 아닙니다.
- **공고** P = {p₁…p_N} — 각 공고에 필수 역량 R(p)와 우대 역량 Q(p)가 있습니다
- **선배 기록** A = {a₁…a_M} — 직무의 진로 분야(taxonomy field)와 겹치는 기록. key_skills를 사용합니다

## 3. 공고에서 역량 추출
1. `keyword`(쉼표 구분) + 직무코드명 + 제목을 구분자(`, / | ·`)로 나눕니다.
2. 항목마다 정확히 정규화되면 그 ID를 씁니다. 아니면 `extractConcepts`(별칭 사전 부분 일치)를 적용합니다.
3. 매핑되지 않은 원문(예: "SAS", "무역")은 `raw_terms`에 남깁니다. 지어내서 매핑하지 않습니다.
4. 사람인 실제 응답에는 필수/우대 구분이 없습니다. 그래서 추출한 역량을 모두 R(p)("공고 언급")로 둡니다. Fixture는 필수/우대를 따로 갖습니다.

한계: 사전 기반이라 동의어 누락과 문맥 오인(예: "R"이 다른 뜻)이 생길 수 있습니다. 공고 본문이 없어 세부 요구를 놓칩니다.

## 4. 정의
- 요구 역량 집합: **D = ⋃_u m(u) ∪ ⋃_p (R(p) ∪ Q(p)) ∪ { s : |{a ∈ A : s ∈ key(a)}| ≥ 2 }**
  - 선배 기록 역량은 1건만 나온 경우 잡음을 줄이기 위해 제외합니다. 단, 다른 출처에 이미 있으면 빈도를 함께 기록합니다.
- 보유(held) = S ∩ D — "보유했다고 **입력한**" 역량
- 미확인(unconfirmed) = D \ S — **보유 여부가 확인되지 않은 역량. 부족하다는 뜻이 아닙니다.**
- held_other = S \ D — 입력했지만 이 직무 근거에는 나타나지 않은 역량

## 5. 우선순위 점수
역량 s에 대해 다음을 계산합니다.
- x_ncs(s) = 1[∃u : s ∈ m(u)]
- x_post(s) = (#{p : s ∈ R(p)} + 0.5·#{p : s ∈ Q(p) \ R(p)}) / N
- x_alum(s) = #{a : s ∈ key(a)} / M

**base(s) = Σ_k w_k·x_k(s) / Σ_{k ∈ 가용} w_k**, 가중치는 w_ncs = 0.3, w_post = 0.4, w_alum = 0.3입니다(설계 가정).

- **가용 출처만 분모에 넣습니다.** N=0(공고 없음)이면 공고 항을 빼고 다시 정규화합니다. 없는 근거를 0점으로 취급해 점수가 낮아지거나, 있는 것처럼 꾸며지지 않도록 하기 위해서입니다.
- 미확인 역량에는 관련 보유 역량 할인을 적용합니다: **priority(s) = base(s) × (1 − 0.3·max_{t∈S} rel(s,t))**. rel은 taxonomy의 역량 관련도(예: sql–database 0.8, python–sql 0.4)이며 0.4 미만은 무시합니다.
- 우선 학습 후보 = 미확인 중 priority ≥ 0.2인 상위 3개. 각 후보에 출처별 근거 문장을 붙입니다. 예: "분석 공고 8건 중 필수 6·우대 2 · 관련 선배 기록 6건 중 5건".
- 성질: 0 ≤ priority ≤ 1. 보유 역량은 후보가 될 수 없습니다. 모든 후보는 1개 이상 출처로 추적됩니다(단위 테스트·A/B/C 평가에서 검증).

## 6. 표시 원칙
- 세 범주: 보유 입력 / 요구·우대 / 미확인
- 공고 빈도에는 **N, 검색어, 조회 시점, 가상 여부**를 항상 함께 표시합니다. 이 빈도는 "검색 표본 내 빈도"이며 시장 전체의 요구 비율이 아닙니다.
- 선배 경험과 공고가 함께 나타나도 인과를 주장하지 않습니다.
- AI 분석 문장은 위 수치로만 만들고 새 사실을 넣지 않습니다.
