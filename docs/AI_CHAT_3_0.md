# AI_CHAT_3_0 — LLM 연결, 의도 분류, RAG, 문맥 관리, 한계

## 1. 연결 구조
```
캠퍼스 대화 패널 → POST /api/lounge/chat (장면 ID, 페르소나, 인사 방식, 최근 대화 6개, 누적 관심 분야)
  → classifyTurn (규칙 기반)
      safety       → 고정 위기 안내 (LLM 미사용)
      real_alumni  → 선배 네트워크 저장소 집계 (LLM 미사용, 사실만)
      smalltalk / character / light / closing → freeTalk: LLM 허용 시 페르소나 짧은 생성, 아니면 템플릿
      clarify      → 관심 분야 칩 (1회)
      career       → 기존 runChat (검색 → 비교 → 근거 기반 생성 → 인용 검증 → 수치 해석 검사)
                     + (채용·역량 질문) Career Intelligence 4역할 근거
  → getProvider(): AI_DEMO_GATE 인스턴스는 시연 세션이 유효할 때만 Qwen3-14B(vLLM), 그 외 CPU Demo
```
- 재사용한 것: bge-m3 임베딩·리랭커 사이드카(있으면 자동 사용, 이번 검증 인스턴스는 로컬 검색), 기존 RAG(`runChat`), 인용 검증, 프롬프트 인젝션 가드레일, Career Intelligence
- 유료 외부 API는 쓰지 않았습니다. LLM은 로컬 vLLM Qwen3-14B입니다(예약 GPU 1, 별도 포트 8019).

## 2. 질문 유형 (지시서 9.2 대응)
| 지시서 유형 | 처리 | RAG |
|---|---|---|
| 1. 일상적인 대화 ("안녕하세요!") | smalltalk → 페르소나 자유 대화 | 미사용 |
| 2. 캐릭터에 관한 질문 ("선배는 나중에 뭐 하고 싶어요?") | character → 가상 캐릭터 설정(좋아하는 것·꿈)을 일관되게 유지하되 AI임을 밝힘 | 미사용 |
| 3. 진로 고민 ("막막해요") | light(공감 + 질문) 또는 career | 상황별 |
| 4. 실제 선배 경험 요청 | real_alumni → 검증된 실제 선배 수·질문 가능 선배 수를 저장소에서 집계해 답하고 게시판 연결 | 미사용(사실 집계) |
| 5. 현재 채용시장 정보 | career + Career Intelligence (Fixture임을 명시) | 사용 |
| 6. 개인화 진로 분석 | career (프로필·누적 관심 분야 반영) | 사용 |
| 7. 로드맵 요청 | career + "나의 로드맵 만들기"·"내 역량 비교하기" 버튼 | 사용 |

## 3. 허위 경험·수치 오해 방지
- **자유 대화 시스템 프롬프트**에서 졸업·취업·합격·면접·인턴 경험을 자기 경험처럼 말하지 못하게 합니다. 2~4문장으로 제한하고, 사실 정보는 말하지 않으며 위기 시 109를 안내합니다.
- **생성 후 검사**(`FABRICATION` 정규식): "제가 졸업했을 때", "내가 다녔던 회사" 같은 표현이 나오면 템플릿으로 대체하고 알림을 붙입니다. 페르소나 한마디(LLM 관점)에도 적용합니다.
- **진로 비교 수치**(Phase A 수정): LLM에 "1에 가까울수록 유리" 정의와 기준별 방향 문장을 결정적으로 전달합니다. 생성 후에는 절 단위 반전 검사와 계산값 해석 목록을 붙입니다. 적합도를 확률로 표현하지 못하게 합니다.
- **출력 정리**: LLM이 프롬프트 태그(`<evidence>` 등)를 옮기면 제거합니다(실제 출력에서 관찰).
- 근거가 없으면 "찾지 못했다"고 답합니다(기존 규칙). 검색하지 않은 자료는 인용할 수 없습니다(인용 검증이 제거).

## 4. 다중 턴 문맥
- 클라이언트는 최근 6개 메시지와 이 대화에서 다룬 관심 분야(`carry`, 최대 6개)를 보냅니다. 이 정보는 sessionStorage에만 있으며 탭마다 분리됩니다.
- 서버는 이번 질문에 도메인 분야가 없으면(예: "그럼 대학원에 가야 할까요?") 이전 발화와 `carry`의 분야를 **이번 요청에만** 프로필에 합칩니다. '대학원·연구'는 경로어로 보고 도메인 전환으로 취급하지 않습니다. 화면에 "앞에서 말한 관심 분야(…)를 이어서 반영했어요"를 표시합니다.
- 서버는 대화를 저장하지 않습니다. 사용자 간 공유도 없습니다. 엔진 결과 10분 캐시는 입력 전체(질문·프로필·이력)의 해시로 조회합니다. 따라서 같은 입력에만 적중하고 다른 사용자의 대화가 섞이지 않습니다.

## 5. 실제 LLM 검증 결과 (2026-11-05, Qwen3-14B, 따뜻한 선배, 수학과 3학년 프로필)
원본: `results/llm3/conversation_qwen3_14b.json` (10턴)

| 대학원과 취업 중 무엇을 먼저…? | 비교 상담 · 32초 | 인용 6건 유효. 방향 검사 이슈 0. "취업은 경제적 부담도 낮은 편"으로 계산값과 일치 |
| 우리 학교 실제 선배의 경험을 알려주세요. | 저장소 집계 · 0ms | "검증된 실제 선배 경험은 아직 없고, 19건은 가상 데이터"라고 정직하게 답함 |
| 실제 선배와 대화할 수 있나요? | 저장소 집계 · 0ms | 질문 가능한 선배가 없다고 안내하고 게시판 연결 |
| 제 상황에서 어떤 역량을 먼저…? | 근거 상담 · 19초 | **5턴 전의 AI 관심을 이어받음**(누적 carry 수정 후). Python·통계 보유를 반영 |

검증 중 발견해 고친 문제
1. 문맥 창이 3개 발화로 짧아 5턴 전 관심 분야를 잃었습니다 → 누적 `carry`를 추가했습니다.
2. `<evidence>` 태그가 답변에 노출됐습니다 → 제거 처리를 추가했습니다.
3. "선배는 어떤 걸 좋아해요?"가 캐릭터 질문으로 분류되지 않았습니다(활용형 '좋아해') → 정규식을 고쳤습니다.
4. 방향 검사가 한 문장 안의 다른 기준 단어("…에 유리하지만, … 더 걸립니다")를 오인했습니다(오탐) → 절 단위 판정으로 바꿨습니다.

모두 회귀 테스트를 추가했습니다. 생성형 모드 **브라우저 E2E**(`campus3-ai.spec.ts`)도 통과했습니다: 비활성 → 60분 시작 → 자유 대화·근거 상담(계산값 해석 포함) → 종료 → 즉시 CPU.

## 6. 한계
- 질문 유형 분류는 규칙 기반이라 미탐과 오분류가 있을 수 있습니다(예: 캐릭터 질문의 새로운 표현).
- 허위 경험 검사는 정규식이라 우회 표현을 놓칠 수 있습니다.
- 수치 방향 검사도 규칙 기반이라 미탐할 수 있습니다. 대신 계산값 해석 목록을 항상 붙여 사용자가 직접 대조할 수 있게 했습니다.
- 근거 상담 응답에 18~32초가 걸립니다(본 답변과 관점 답변의 2회 생성, 단일 L40S 기준). 시연 시 대기 표시가 필요합니다.
- 자유 대화에서 LLM이 캐릭터 설정을 "오늘 벤치에 앉아 있었는데"처럼 장면 묘사로 쓰는 경우가 있었습니다. 가상 캐릭터 설정의 범위로 보고 허용했지만, 운영 전에 문구 기준을 검토해야 합니다.
- 이번 검증 인스턴스는 GPU 임베딩 사이드카 없이 로컬 검색을 썼습니다(bge-m3 연동 경로는 2.0 이전부터 있던 코드이며 이번에 다시 검증하지 않았습니다).
