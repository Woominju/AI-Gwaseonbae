# 홈페이지 배포 안내

GitHub에 코드를 올리는 것과 인터넷에서 접속되는 서비스를 운영하는 것은 별개입니다. 이 문서는 현재 코드를 점검해 정리한 안내이며, **실제 배포는 수행하지 않았고 Vercel 등 외부 환경에서 시험하지도 않았습니다.** 요금과 사용 제한은 자주 바뀌므로 각 서비스의 공식 페이지에서 확인하세요.

## 1. 현재 구조 점검
| 구성요소 | 현재 구현 | 배포 시 의미 |
|---|---|---|
| 웹서버 | Next.js 15 (`next start`, Node 22) | Node 서버면 어디서나 실행 가능 |
| 상담 API | `/api/lounge/chat`, 최대 120초 | 서버리스의 함수 실행 시간 제한 확인 필요 |
| LLM | vLLM + Qwen3-14B (OpenAI 호환) 또는 CPU 템플릿 | 웹서버와 **분리된 GPU 서버** 필요 |
| GPU | 검증 환경 NVIDIA L40S, 할당 약 40GB (설정 비율 0.88 기준, 모델 소비 약 28GB) | 일반 웹 호스팅으로 불가 |
| 임베딩·리랭커 | `ml/server.py` FastAPI + BGE-M3 등. 검증 시 GPU 메모리 약 2.6GB | 선택. 없으면 로컬 n-gram 검색으로 동작 |
| 관계 그래프 | 요청마다 메모리에서 구성 | 별도 그래프 DB 불필요 (현재 규모) |
| 저장소 | `web/data/` JSON 파일 (선배 네트워크, Q&A, AI 시연 상태) | **쓰기 가능한 영구 디스크 필요** |
| 속도 제한·응답 캐시 | 프로세스 메모리 | 인스턴스가 여러 개면 공유되지 않음 |
| 학생 프로필 | 브라우저 저장 | 서버 저장 없음 |

## 2. JSON 저장의 한계와 데이터베이스
파일 저장소는 프로세스 1개를 전제로 합니다. 서버가 여러 대이거나 서버리스 환경이면 데이터가 사라지거나 동시 쓰기가 충돌합니다. 시연용 읽기 전용이면 DB가 필요 없습니다. **실제 선배 정보, 동의, Q&A를 받으려면 PostgreSQL 같은 영구 DB, 백업, 접근 기록이 먼저 필요합니다.** `store.server.ts` 파일들을 DB 구현으로 교체해야 하며 아직 구현되지 않았습니다.

## 3. 환경변수와 비밀정보
- `.env.example`이 전체 목록입니다. 실제 값은 호스팅 서비스의 환경변수 설정에만 넣고 저장소에 올리지 않습니다.
- `SESSION_SECRET`은 32자 이상 임의 값, `ADMIN_TOKEN`은 12자 이상 임의 값을 씁니다. E2E의 `test-admin-token-123456`은 운영에 쓰면 안 됩니다.
- 공개 시연에서는 `ADMIN_TOKEN`을 비워 관리자 기능을 닫는 것을 권장합니다.

## 4. 인증과 접근 제어
현재 역할은 초대 코드와 서명 쿠키 기반이며 학교 SSO가 없습니다. 실제 학생을 대상으로 하려면 SSO, 개인정보 처리방침, 삭제·철회 절차 검토가 필요합니다. 외부에 여는 시연은 `PUBLIC_DEMO=1`을 켜세요 (관리자·쓰기 차단, 가상 데이터만 사용, 요청 속도 제한). 시연 범위를 좁히려면 접근 제어 프록시를 함께 쓰는 것이 안전합니다.

## 5. 다중 사용자
- LLM 동시 요청은 GPU 성능에 묶입니다. `AI_DEMO_MAX_CONCURRENCY` 등으로 제한합니다. 제한을 넘으면 템플릿으로 대체됩니다.
- 측정: 첫 답변 약 15~18초 (단일 요청). 동시 부하 시험은 하지 않았습니다.
- 응답 스트리밍이 없어 답변이 끝날 때까지 기다립니다.

## 6. 정적 자산과 모델 서버 분리
화면과 일러스트는 코드로 그린 SVG와 번들 글꼴이라 웹서버에서 제공됩니다. 모델 서버는 **절대 인터넷에 그대로 열지 않습니다.** 사설망이나 VPN 안에 두고, 웹서버의 `LOCAL_LLM_BASE_URL` 또는 `LLM_BASE_URL`로만 접근하게 하세요.

## A. CPU Demo 홈페이지 배포
GPU 없이 **템플릿 응답과 가상 데이터**로 기능을 보여 줍니다. 화면에 CPU Demo로 표시되며 생성형 AI가 아닙니다.

| 장점 | 단점 |
|---|---|
| GPU 비용 없음, 가장 단순 | 생성형 AI 답변 없음 |
| 실제 개인정보를 다루지 않음 | 선배 네트워크 쓰기 기능을 쓸 수 없음 |

**준비물:** 호스팅 계정, 패키지를 올린 GitHub 저장소, 학교 명칭 사용 확인.

### A-1. Vercel을 쓰는 경우
**적합한 부분:** Next.js 화면과 읽기 위주 API. **맞지 않는 부분:** JSON 파일 쓰기(서버리스 파일시스템은 영구적이지 않음), 메모리 기반 속도 제한(인스턴스 간 공유 안 됨). 공개 잠금 모드의 Node 미들웨어 동작은 시험하지 않았으니 배포 후 반드시 확인하세요.

1. Vercel에서 GitHub 저장소를 가져오고 **Root Directory를 `web`** 으로 지정합니다.
2. 환경변수를 넣습니다: `LLM_PROVIDER=demo`, `PUBLIC_DEMO=1`, `FEATURE_CAMPUS_LOUNGE=1`, `FEATURE_CAREER_INTEL=1`, `FEATURE_COURSE_GRAPH=1`, `SESSION_SECRET=<임의 값>`. `ADMIN_TOKEN`은 비웁니다.
3. 배포 후 확인합니다: `/`, `/campus`, `/graph?view=explore`, `/api/status`의 `public_demo: true`, `/admin`의 404.

### A-2. 일반 Linux 서버(VPS)를 쓰는 경우
```bash
cd web && npm ci && npm run build
PUBLIC_DEMO=1 LLM_PROVIDER=demo FEATURE_CAMPUS_LOUNGE=1 FEATURE_CAREER_INTEL=1 FEATURE_COURSE_GRAPH=1 \
  SESSION_SECRET=<임의 값> npx next start -H 127.0.0.1 -p 3000
```
앞단에 HTTPS 리버스 프록시(Caddy, Nginx 등)를 두고, 프로세스 관리자로 재시작을 설정합니다. 실행 중인 서버 폴더에서 다시 빌드하면 화면이 멈출 수 있으니, 새 폴더에 빌드한 뒤 교체하세요.

## B. 실제 생성형 AI 연결 배포
**Vercel만으로는 불가능합니다.** 웹은 Vercel이나 VPS에 둘 수 있지만, 모델은 GPU 서버가 별도로 필요합니다.

```
브라우저 → 웹 서버(Next.js) → GPU 서버(vLLM, 선택: 임베딩·리랭커)
                ↓
          영구 DB (실제 데이터를 받을 때)
```

| 장점 | 단점 |
|---|---|
| 실제 생성형 상담 | GPU 서버 비용과 운영 부담 |
| 데이터가 자체 관리 범위에 있음 | 모델 서버 보안, 동시 요청 제한 필요 |

**비용 구조:** 웹 호스팅(작음) + GPU 서버(가장 큼, 켜 둔 시간만큼) + DB(실제 데이터 시) + 도메인. 시연 시간에만 GPU를 켜면 크게 줄어듭니다. `AI_DEMO_GATE=1`이 이 운영을 지원합니다. 외부 LLM API를 쓰면 GPU 대신 토큰 비용이 듭니다.

**준비물:** GPU 서버(검증 환경 기준 VRAM 약 40GB 할당, 더 작은 환경은 설정 조정과 별도 시험 필요), 사설 연결, 모델 라이선스 확인, 웹 호스팅.

**순서**
1. GPU 서버에 Python 환경을 만들고 `pip install -r ml/requirements.txt` 합니다.
2. vLLM을 내부 주소로만 띄웁니다. `LLM_GPU=<GPU 번호> LLM_PORT=8009 bash scripts/start_llm.sh`
3. (선택) 임베딩: `ML_GPU=<GPU 번호> ML_PORT=8008 bash scripts/start_ml.sh`
4. 웹 서버와 GPU 서버를 VPN·사설망으로 연결하고 방화벽으로 포트를 제한합니다.
5. 웹 환경변수: `LLM_PROVIDER=local`, `LOCAL_LLM_BASE_URL=http://<GPU 서버 내부 주소>:8009/v1`, `LOCAL_LLM_SERVED_NAME=local-llm`, `AI_DEMO_GATE=1`, 동시성 제한. 필요하면 `ML_SERVICE_URL`.
6. 접속 후 상단에 "생성형 AI 상담"이 표시되는지 확인합니다. 서버가 응답하지 못하면 템플릿으로 대체되는지도 확인합니다.
7. 실제 동문 데이터를 받기 전에 DB, 동의 절차, 삭제·철회, 학교 SSO를 먼저 갖춥니다.

**외부 API를 쓰는 경우:** `LLM_PROVIDER=openai_compatible`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`를 설정합니다. 이 경로는 코드에 있지만 이번에 실제 유료 API로 시험하지 않았고, 질문 내용이 외부로 전송되므로 지출 한도와 개인정보 검토가 먼저 필요합니다.

## 공개 전 공통 점검
- 학교 명칭·이미지 사용 승인
- 위기 대응 안내의 전문가 검토와 학교 상담센터 연락처 확인
- 공식 수강편람 사용 허가 (현재는 가상 데이터)
- 화면의 "가상 시연 데이터" 표시 유지
