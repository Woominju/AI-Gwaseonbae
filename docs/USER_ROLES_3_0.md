# USER_ROLES_3_0 — 학생·실제 선배·관리자 인증 및 권한

> Feature Flag `FEATURE_ALUMNI_NETWORK=1`일 때만 동작합니다. 공개 시연(`PUBLIC_DEMO=1`)에서는 모든 쓰기·개인 기능이 404이고, 실제 선배 데이터는 노출하지 않습니다.
> **현재 학교와의 동문 인증 협의는 진행 전입니다.** 실제 동문 인증 인프라(학교 SSO, 졸업생 DB 조회)가 없습니다. 그래서 "운영자가 오프라인으로 확인한 뒤 1회용 인증 코드를 발급"하는 최소 구조만 구현했습니다.

## 1. 역할과 획득 방법
| 역할 | 얻는 방법 | 서버 검증 | 세션 유효 기간 |
|---|---|---|---|
| 학생 (student) | 첫 화면 "학생으로 시작" → `POST /api/session/student`. 익명 ID만 발급하고 개인정보는 받지 않음 | 서명 쿠키 | 30일 |
| 실제 선배 (alumni) | 관리자가 발급한 **1회용 인증 코드**를 `/alumni/join`에서 입력 → `POST /api/alumni/redeem` | 코드 해시 대조·미사용·만료(14일) 확인 후 서명 쿠키 | 7일 |
| 관리자 (admin) | `/admin/alumni`에서 서버 환경변수 `ADMIN_TOKEN`(12자 이상) 입력 → `POST /api/admin/login`. 스크립트는 `x-admin-token` 헤더 사용 가능 | 상수 시간 비교 | 4시간 |

- **클라이언트에서 역할을 바꿔도 권한이 생기지 않습니다.** 세션은 `HMAC-SHA256(SESSION_SECRET)`으로 서명한 HttpOnly·SameSite=Strict 쿠키입니다. 역할을 변조하면 서명 검증에 실패합니다(단위 테스트로 검증).
- "선배로 참여" 버튼은 인증 코드 입력 화면으로 이동시킬 뿐 역할을 부여하지 않습니다.
- `SESSION_SECRET`이 없으면 프로세스마다 임의 비밀값을 만듭니다. 이 경우 재시작하면 모든 세션이 무효가 됩니다. 운영 시에는 반드시 설정해야 합니다.
- 관리자 로그인과 인증 코드 입력은 IP별로 10분에 10회까지 시도할 수 있습니다.
- API는 JSON 요청만 처리합니다. 쿠키가 SameSite=Strict여서 CSRF 위험이 낮습니다.

## 2. 실제 선배 데이터 흐름
```
관리자: 동문 신원 확인(학과·운영 절차, 오프라인) → 인증 코드 발급(원문은 1회 표시, 해시만 저장)
선배: 코드 입력 → 인증됨(verified) → 경험 등록(공개 동의 필수, AI 인용 동의 선택) → 상태 pending
관리자: 검토 → 승인/반려 (미인증 선배의 경험은 승인 불가)
공개: 승인 + 검증 + 공개 동의 → /alumni 게시판
AI 근거: 승인 + 검증 + 실제(비시연) + AI 인용 동의 → RAG 레코드(A-001…, is_synthetic=false, "실제 선배" 배지)
질문: 학생 → 질문 수신 동의(mentoring_opt_in)한 검증 선배에게만. 학생당 하루 5개. 답변은 질문한 학생에게만 보임
철회: 선배가 철회 요청 → 관리자 처리 시 비공개·경험 철회·미답변 질문 종료
```

- **시연용 계정(demo)**: 관리자가 "시연용 코드"로 발급한 계정입니다. "시연용 계정" 배지가 붙고, 실제 동문 수에 포함되지 않으며 RAG에도 들어가지 않습니다. 테스트와 시연은 이 경로로만 진행했습니다.
- 경험 입력 검증
  - 연락처·이메일·주민번호·학번 패턴을 거부합니다.
  - 프롬프트 인젝션 패턴을 거부합니다.
  - 필드 길이를 제한합니다.
  - 분야와 경로는 허용 목록에서만 받습니다.
- 공개 범위: 학생에게만(기본) / 공개 / 익명(학과만)

## 3. 화면
| 경로 | 대상 | 기능 |
|---|---|---|
| `/` | 모두 | 학생으로 시작 / 선배로 참여 |
| `/alumni` | 모두 | AI 선배와 실제 선배의 차이 안내, 집계(실제·시연 구분), 승인된 경험 게시판, 질문 가능 선배 목록과 질문 남기기, 내 질문·답변 |
| `/alumni/join` | 선배 | 인증 코드 입력 |
| `/alumni/me` | 인증 선배 | 질문 받기 설정, 공개 범위, 경험 등록과 상태, 받은 질문 답변, 철회 요청 |
| `/admin/alumni` | 관리자 | 인증 코드 발급(시연용/실제), 검토 대기 승인·반려, 선배 철회 처리, 신고 처리, 감사 로그, AI 시연 모드 제어 |

## 5. 저장소와 한계
- 저장 위치는 `web/data/alumni/store.json`(git 제외, 디렉터리 0700·파일 0600)입니다. 단일 프로세스 JSON 파일이므로 동시 쓰기, 백업, 암호화는 운영 단계에서 DB로 바꿔야 합니다.
- 감사 로그(누가·무엇을·언제)가 남습니다. 관리자는 단일 토큰 계정입니다. **다중 관리자·역할별 권한·학교 SSO는 미구현**입니다.
- 실제 동문 신원 확인 절차(졸업 증명 등)는 시스템 밖의 운영 절차이며 아직 정해지지 않았습니다.
- 신고 기능은 API와 관리자 처리 화면이 있습니다. 메시지별 신고 버튼 UI는 일부(관리자 처리)만 구현했습니다.
